## 실험 중 발견하고 고친 오류

첫 보드 실행에서 밸브 절차의 `VALVE_FB == 75.5를 2초 유지. 허용시간 8초.`를 모델이 잘못 구조화했다. 조건을 두 개로 나누거나, 2초를 허용시간으로 넣고 유지시간을 0으로 남겼다. 원문 대조가 이를 거절했으나, 오류를 하나씩만 전달해 세 번의 응답으로 수정이 끝나지 않았다.

원문 대조가 조건 개수·허용시간·유지시간의 불일치를 함께 전달하도록 바꿨다. `N초 유지` 표현도 프롬프트에 명시했다. 최종 실험에서는 이 단계가 첫 응답에서 실패한 뒤 **한 번의 재시도로 수정**됐다. 모델 원응답이 항상 맞게 된 것은 아니다. 잘못된 출력을 승인 전에 발견하고 제한된 재시도 안에서 바로잡은 결과다.

## 보고서 방식 변경

기존에는 모델의 자유 조치 문장을 숫자·문자 규칙으로 검사했다. 근거 없는 원인 단정이 통과할 수 있었고, 한 항목이 틀리면 전체 문안이 기본 문안으로 바뀌었다.

현재는 엔진의 실제 단계·사유에 연결된 후보를 제시하고 AI가 ID를 선택한다. 앱이 후보에 지정된 문장을 표시하며 자유 생성 문장은 사용하지 않는다. 잘못된 선택은 항목별로 제외하고, 유효한 선택이 없을 때만 재시도·기본 항목으로 전환한다. 저장된 ID도 표시할 때 다시 확인한다. 요약·상태·시간·측정 근거는 계속 규칙 엔진이 작성한다.

7개 검사는 정상, 기동 지연, 온도 회복 지연, 결측, 미기동, 중단 조건 발생, 조기 스트림 종료이다. 결과와 선택한 항목은 [evaluation.json](final/evaluation/evaluation.json)에 기록했다. 이는 점검 항목 선택의 성공이며 자유 문장 생성 품질이나 고장 원인 진단 정확도 측정이 아니다.

## 격리 조건과 NPU 증거

앱과 설치된 GenieX 모델을 같은 Linux 사용자·네트워크·마운트 네임스페이스 안에서 실행했다. 보드 관리 접속은 밖에 유지했으므로 **보드 전체의 물리적 망 분리 시험은 아니다.** 모델 파일은 사전에 설치된 캐시를 사용했다.

- 내부 인터페이스는 `lo`뿐이며 IPv4·IPv6 외부 기본 경로가 없다.
- 시작과 종료 상태에서 DNS·공개 IP TCP 연결이 차단됐다. 점검 생략 옵션은 사용하지 않았다.
- 앱과 모델의 네트워크 네임스페이스 ID가 같고 관리용 SSH 프로세스와 다르다.
- 실제 모델 프로세스에서 QNN HTP 라이브러리와 `/dev/fastrpc-cdsp1-secure` 사용을 확인했다.
- `tx_delta_bytes=0`은 외부 인터페이스가 없어 송신 통로가 없다는 상태값이다. 별도 패킷 캡처나 보드 전체 트래픽 측정 결과로 해석하지 않는다.

원자료: [전체 흐름 결과](final/lifecycle/results.json), [인터페이스](final/interfaces.json), [IPv4 경로](final/routes.json), [IPv6 경로](final/routes6.json), [프로세스 격리 대조](final/namespace-processes.json), [시작 상태](final/status-start.json), [종료 상태](final/status-end.json), [파일 해시](final/manifest.json).

보드 서버 재시작 후 이력 검사는 [history-restart.json](final/history-restart.json)에 기록했다. 저장된 NPU 기록의 수정하지 않은 복사본을 PC 브라우저에서도 확인했다([화면 검사](final/saved-history-ui.json), [FAIL 기록 화면](final/fail_start-report.png)).

## 재현

보드에 호환 NPU 런타임·모델과 프로젝트 가상환경이 준비돼 있어야 한다. 사용하지 않는 검증용 체크아웃에서 실행한다. 이 스크립트는 모델 설치나 호스트 네트워크 설정 변경을 수행하지 않는다.

```bash
# manifest.json: 테스트할 소스의 commit과 파일별 SHA-256을 기록한 JSON
# 이미 있는 파일을 검사한다. 예시 구조는 final/manifest.json 참고.
bash scripts/airgap_npu_test.sh sessions/_isolated-npu manifest.json
```

가상환경이나 GenieX의 경로가 다르면 `CXPE_PYTHON`, `CXPE_GENIEX_BIN`으로 지정한다. 스크립트는 자신이 시작한 앱·모델 프로세스를 종료한다. 호스트 관리 접속과 다른 서비스는 유지한다.

일반 로컬 모델 검사는 `python scripts/evaluate_npu.py --out sessions/_npu-evaluation`로 실행할 수 있다. 자동화 회귀는 `python -m pytest`이다.

## 범위와 한계

6건은 개발 중 확인한 합성 회귀 자료이다. 실제 현장 문서의 범용 정확도, 업무시간 단축률, 비용 절감률, 전력 절감률은 측정하지 않았다. 제목·조치·복구는 원문을 복사하며, AI가 의미를 새로 생성한 결과로 세지 않는다. 추출 비교에서 엔진의 사전조건·트리거 대기 설정은 제외하고 앱 기본값 적용을 별도로 검사한다.

지원 형식, 입력 오류 처리와 미구현 범위는 [입력 검증과 AI 활용 범위](../../validation-scope.md)에 정리했다. 실제 현장 문서·태그·측정 기록을 이용한 병행 검증과 PDF/OCR·BMS 연동은 후속 작업이다.
