## 최초 재검증에서 발견한 문안 문제와 보완

세션 보존 수정이 병합된 `9385058`에서 먼저 실기 시험을 수행했다. 추출·판정·이력 검사는 통과했지만 보고서 직접 검토에서 다음 문제가 발견됐다.

- 정상 시험의 관측 소요시간 40초를 후속 조치의 새 기준처럼 제시했다.
- 기동 지연 뒤 미실행된 단계까지 통과한 것처럼 요약했다.
- 계측 결측 조치에 깨진 문자가 포함됐다.

따라서 판정 요약은 엔진 결과로 고정하고 AI 역할을 후속 조치 검토 문안으로 한정했다. AI 조치의 수치 및 문자 검증에 실패하면 전체 조치 목록을 기본 문안으로 대체한다. 회귀 테스트 9개를 추가한 뒤 최종 코드 `d8291a6`에서 위 세 상황을 다시 실행했다.

최초 결과는 이 폴더의 `pass/`, `fail_start/`, `fail_dropout/`, [results.json](results.json)에 보존했다. 최초 `success: true`는 당시 자동화한 실행·이력 항목의 통과를 뜻하며, 문안 품질까지 통과했다는 뜻은 아니다. [최초 문안 검토](manual-review-initial.json)는 실패를 명시한다. **제출 코드의 최신 근거는 `final/` 아래 자료를 사용한다.**

## 조치 문안 대체의 해석

최종 첫 보고서 3건, 각 보고서 재생성, 재시작 후 정상 보고서 재생성에서도 조치 문안의 출처는 `template(llm-guard)`였다. 엔진의 판정 요약·표·근거는 정상 생성됐지만, 모델이 작성한 조치 문안의 채택률은 이번 첫 보고서 표본에서 0/3이다.

실행 후 같은 입력으로 수행한 [별도 진단 요청](final/report-diagnostic.json)에서는 다음을 확인했다. 이는 원래 거절된 응답을 복원한 자료가 아니라 후속 추론의 응답이다.

- 정상 상황: `CH1`, `CH2`라는 축약 표기가 등록된 `CH-1`, `CH-2` 또는 태그와 정확히 일치하지 않아 숫자 검증에서 거절됐다. 표기 차이에도 기본 문안으로 대체하는 보수적인 제한이다.
- 기동 지연: 조치 문안에 `CH2_STATUS=1`, `30초`를 다시 넣어 숫자 검증에서 거절됐다.
- 계측 결측: 조치 문안에 `5초`, `65.0초`를 다시 넣어 숫자 검증에서 거절됐다. 일부 다른 문장도 자연스러운 한국어라고 보기 어려웠다.

현재 검증 규칙은 모든 문장의 의미나 자연스러움을 보장하지 않는다. 자연어 조치 생성 품질 개선은 남은 과제이며, 제출 설명은 **AI의 절차 구조화 + 승인 규칙 기반 판정·기록 + 조치 문안 검증·대체**로 표현하는 것이 맞다.

## 검증 한계와 종료 상태

- 입력은 합성 시계열이며 실제 설비를 제어하지 않았다. BMS/BACnet 실시간 연동, 장기 부하 시험, 현장 업무시간 절감률을 측정하지 않았다.
- 동일 문서 1건을 세 번 추출한 결과다. 기존 F1 0.843 측정의 전체 평가를 최신 코드로 다시 수행한 자료가 아니다.
- 외부 네트워크가 연결된 보드에서 로컬 NPU를 사용했다. AI를 포함한 전체 흐름의 완전 격리·외부 송신 0건을 입증한 결과가 아니다. 인터페이스 송신 증가량은 앱만의 외부 송신량이 아니다.
- 검증 후 프로젝트 소유의 서버·GenieX 서비스를 중지했고 8080·8089·18181 포트 종료를 확인했다. 다른 프로젝트 서비스와 모델 설정은 변경하지 않았다. [정리 결과](final/cleanup.json)
