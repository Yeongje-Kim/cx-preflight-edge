# 제출 코드 검증

검증일: 2026-09-07. Windows PC의 Python 3.11 가상환경과 Chrome에서 확인했습니다.

## 수정한 두 문제

- 같은 세션을 다시 실행할 때 이전 SSE 완료 이벤트와 결과 파일이 섞이는 문제: 세션당 실행을 한 번으로 제한하고, 재시험은 새 세션에서 시작하도록 변경했습니다. 서버가 실행을 수락한 뒤 SSE를 연결하며, 구독 직후 완료되더라도 대기 중인 판정·보고서 이벤트를 끝까지 전달합니다.
- 시험이 끝난 뒤 재승인하면 과거 보고서의 기준이 달라지는 문제: 실행 당시 승인 규칙을 `rules.executed.json`으로 보관하고 보고서 재생성 시 사용합니다. 실행한 세션은 강제 옵션을 사용해도 재승인·재실행할 수 없습니다.

동일 세션의 승인과 실행 시작은 단일 서버 프로세스 안에서 직렬화했습니다. 실행·보고서 작성 중에는 삭제와 별도 보고서 재생성도 차단합니다. 이전 버전의 결과 파일도 검사해 서버 재시작 후 재실행을 막습니다. 기존 세션에 실행 규칙 보관본이 없는 경우 저장된 승인본으로 보고서를 열 수 있지만, 이미 덮어쓴 과거 기준을 복원하는 기능은 아닙니다.

## 실행 결과

| 검사 | 결과 |
|---|---|
| `python -m pytest` | 87개 통과. 기존 78개와 세션 수명·SSE 회귀 9개 |
| `python -m pip check` | 의존성 충돌 없음 |
| `node --check web/app.js` | 문법 검사 통과 |
| 새 가상환경 설치 | README의 pip install -e 명령 성공, 별도 환경에서 87개 재통과 |
| Linux 격리 스크립트 | 완료 상태 대기·오류 종료 보완, bash 구문 검사 통과. 이번 PC 검사에서 실제 격리 실행은 하지 않음 |
| CLI 정상 사전검증 | 결함 없음 |
| CLI 기동 지연 재생 | S5 FAIL, 초과 구간 58~72초 |
| 합성 CSV 생성 후 CLI 재생 | 8단계 PASS |
| 새 합성 지표 집계 | 사전검증 P/R 1.000, 단계 판정 240/240 일치 |
| Chrome 브라우저 | 아래 5개 상황과 이력·오류 복구·화면 폭 검사 통과 |

브라우저는 절차 결함의 승인 차단, 정상 PASS, 기동 지연 FAIL, 온도 회복 지연 FAIL, 계측 결측 HOLD를 확인했습니다. 완료한 세션의 승인·실행 버튼 비활성화, 새 시험마다 다른 세션 생성, 저장된 HOLD 세션 복원, 생성 요청 503 오류 후 재시도 가능 상태도 확인했습니다. 1600·1280·768·390px에서 가로 화면 넘침이 없었고 JavaScript 오류는 없었습니다.

브라우저 결과와 화면은 [submission-review](screens/submission-review/results.json)에 있습니다. 테스트 스크립트는 `scripts/ui_review.cjs`이며 별도의 Playwright와 Chrome이 필요합니다. `CXPE_UI_BASE`로 실행 중인 테스트 서버 주소를 지정할 수 있습니다.

## 측정 범위

이번 자동화 검사는 FakeBackend 또는 기준 규칙을 사용했습니다. 최신 세션 보존 수정 후 실제 NPU 추론과 AI 포함 완전 격리 시험을 새로 수행한 결과는 아닙니다. 기존 보드 측정과 후속 추출 검증은 별도 문서에 날짜와 조건을 보존했습니다.

현재 구조는 단일 서버 프로세스 기준입니다. 실제 BMS/BACnet 수집, 설비 제어, 사용자 인증, 프로젝트 현장 적용과 업무시간 절감률은 이번 검증 범위에 포함되지 않습니다. pytest 실행 중 의존성 사용 중단 예고 및 의도적으로 잘못된 필드를 주입하는 테스트의 직렬화 경고가 있었으며, 실패한 테스트는 없었습니다.

새 설치 환경의 주요 패키지: Python 3.11, FastAPI 0.141.1, Starlette 1.6.0, Pydantic 2.13.5, Uvicorn 0.52.4, pytest 9.1.1. 2026-09-07 설치 시점 기준입니다.
