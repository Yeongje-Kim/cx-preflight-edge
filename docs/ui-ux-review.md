# 웹 UI·UX 및 공모전 적합성 검토

검토일: 2026-09-07 (한국 기준). 대상: `cx-preflight-edge/web`, Qualcomm AIRbox Q900의 기존 서버.

## 판단

제품의 방향은 공모전 분야 ② 시공·품질관리와 연결된다. 통합시운전 엔지니어가 절차의 결함을 사전에 확인하고 승인한 기준으로 시험 결과를 기록하는 업무 흐름이 핵심이다. 기존 화면은 기능은 갖췄지만 원문·규칙 표·승인·재생 설정이 동시에 보여 사용 순서를 설명해야 했고, 실행 결과와 기술 로그의 시각적 우선순위가 약했다.

개선본은 검토 → 승인 → 판정·기록의 순서와 다음 행동을 명시한다. 공모전에 가장 적합한 UI라는 절대적 결론이나 수상 점수는 부여하지 않는다. 심사위원·실무자 대상 사용성 조사는 아직 하지 않았다.

## 변경

- 준비 화면에 업무 목적, 3단계 진행 표시, 현재 상태에 맞는 다음 행동 추가.
- 시연 상황을 한국어로 표시하고 기준 문서 사용과 실제 AI 추출을 구분.
- 원문·규칙 표·AI 보조 제안·장치 상세·예외 승인·시험 기록을 접이식으로 정리. 규칙 자체는 승인 전에 열어 검토할 수 있음.
- 명시적 검토 확인 전에는 승인 불가. ERROR가 남으면 기본 승인을 비활성화. 기존 예외 승인 API 기능은 별도 설정에 유지하고 기록됨을 안내.
- 실행 화면 최상단에 판정 결과와 계통 상태, 그 아래에 차트와 기대조건 근거 배치. 사전·중단 조건은 펼쳐 확인. 단계별 기록과 타임라인도 필요할 때 표시.
- 실패·보류 시점 고정, 허용시간 초과 구간, 기존 모식도와 차트 유지.
- 모바일 표 넘침 수정, 키보드 초점 표시, 요청 실패 안내와 재시도, 새 시험 생성 시 이전 승인 초기화, 저장된 시험의 시연 조건 복원.
- 결함 주입 규칙을 AI 추출 결과로 오해하지 않도록 출처 표시. 합성 데이터와 설비 제어 없음 고지 유지.

## 검증 결과

- 로컬과 보드: 기존 pytest 58개씩 통과. 기존 의존성의 deprecation warning 존재.
- Chrome 자동화: 절차 결함은 검토 확인 후에도 기본 승인 차단, 정상 PASS, 기동 지연 FAIL, 온도 회복 지연 FAIL, 결측 HOLD.
- S5: 허용 30초, 마감 58초, 후속 시계열의 실제 성립 72초, 초과 구간 58→72 확인. 판정 시각은 1Hz 샘플 조건상 59초이며 마감 58초와 다름.
- 보고서 표시, 저장된 HOLD 세션 다시 열기, HTTP 503 요청 실패 시 안내 및 재시도 가능 상태 확인.
- 1600·1280·768·390px 화면 폭 점검. 390px에서 페이지 전체 가로 넘침 없음. 모식도와 상세 규칙 표는 내부 가로 스크롤 사용.
- 브라우저 JavaScript 오류 없음. 캡처에서 준비 화면·FAIL·모바일 HOLD 배치 시각 검토.
- 로컬 결과: `docs/screens/ui-review/results.json`. 보드 결과: `docs/screens/board-ui-review/results.json`.
- 이번 UI 테스트는 합성 SIL 데이터 기반이며 기존 모델 정확도·지연 벤치마크를 다시 측정한 것이 아니다. 화면의 개별 지연 수치를 기존 성능 대장 대신 사용하지 않는다.

## 추천 시연 순서

1. 결함 발견: 사전검증 시작 → ERROR 2건과 승인 차단 → 해당 규칙 펼쳐 확인.
2. 정상 시험: 기준 검토 → 검토 확인 → 승인 → 재생 → PASS.
3. 기동 지연: S5 FAIL, 허용 30초와 58→72초를 판정 카드·차트로 설명.
4. 결측: S7 HOLD, 계측 결측을 설비 불합격으로 단정하지 않음을 설명.
5. 실제 AI 추출 출처와 시험 기록 초안을 보여주고 엔지니어 최종 검토로 마무리.

## 적용 및 재현

보드 주소: http://100.72.78.38:8080 (Tailscale 접속 필요).
웹 파일 3개만 반영. 보드의 반영 전 파일은 `~/cx-preflight-edge/docs/ui-backup-20260907/`에 보관. 기존 서비스 설정과 다른 온디바이스 프로젝트는 변경하지 않음. Git 커밋·푸시는 수행하지 않음.

재현 스크립트: `scripts/ui_review.cjs`. Node.js, Playwright, 로컬 Chrome 필요. `CXPE_PLAYWRIGHT`에 설치된 Playwright 모듈 경로를 지정할 수 있다. 서버를 먼저 실행하고 저장소 루트에서 실행한다. 검증 시 합성 시험 세션이 생성된다.

```powershell
$env:CXPE_UI_BASE='http://100.72.78.38:8080'
$env:CXPE_UI_CAPTURE='board-ui-review'
node scripts/ui_review.cjs
```

현장 사용성 확인에서는 엔지니어에게 설명 없이 결함 찾기·승인·FAIL 이유 설명·기록 찾기를 수행하게 하고, 작업 시간과 막힌 지점을 기록하는 것이 다음 단계다.

## 실제 LLM 추가 검증: 제출 전 해결 필요

보드 세션 `cx-20260906-225547-b973`, 백엔드 `geniex-18181`: 실제 AI 추출 8/8 단계 완료, 승인·재생·보고서 생성까지 동작했지만 **정상 합성 데이터의 기대 PASS 검증은 실패**했다. UI JavaScript 오류는 없었다.

- 기준 S2: `LOAD_KW >= 200`, 허용 30초, 유지 10초.
- 이번 AI 추출 S2: `LOAD_KW > 200`, 허용 10초, 유지 30초.
- 바뀐 규칙을 승인하자 단계 진행이 지연되어 S3에서 `CH1_STATUS == 1` 사전조건 미충족 FAIL.
- Preflight는 ERROR 0건으로 이 의미 추출 오류를 잡지 못했다. 스키마 통과·사전검증 통과·AI 제안 존재만으로 원문과 의미가 일치한다고 볼 수 없다.
- 추가 차이: S7 `changes_state` false→true, S8 트리거 대기시간 180→120초. 이번 실패의 직접 관측 원인은 S2 시간 조건 변환이다.

화면 보완: 허용/유지 시간을 `10/30`처럼 압축하지 않고 각각 이름과 단위를 표시한다. 실제 AI 추출 완료 시 원문 대조 안내를 표시하고 규칙과 원문을 자동으로 펼친다. 이 안내는 모델 추출 오류를 수정하거나 승인 규칙을 자동 교정하는 기능은 아니다.

따라서 기준 문서 기반 5개 케이스 통과와 실제 LLM 경로의 정상 시나리오 실패를 분리해 보고한다. 공모전 제출 전에는 숫자·연산자·시간 조건의 원문 대조 및 수정·재검증 절차를 보완해야 한다. 이번 작업에서는 모델 프롬프트·규칙 엔진을 변경하지 않았다. `docs/screens/board-ui-review/llm-result.json` 및 `llm-normal-input-failed.png`에 당시 결과를 보존했다. 정상 입력 시나리오의 실제 결과가 FAIL임을 캡처 이름에도 표시했다.



## 후속 수정 완료 (2026-09-07)

위 실제 AI 추출 실패는 `source-extraction-fix.md`의 수정과 재검증으로 후속 처리했다. 원문 수치 대조와 재추출, 원문 대조를 통과한 기준 단계만 대체하는 경로, 승인·재생 차단을 추가했다. 수정 후 보드 실제 AI 전체 흐름은 8/8 단계 원문 대조·기준본 대체 0건·정상 PASS로 완료했다. 기존 실패 증거는 비교를 위해 보존한다.
